# P2 , Lensa INTERAKSI & MOTION (dinding ucapan Khadizah & Anwar)

Konteks kunci yang membentuk semua keputusan di bawah:
- Kad ucapan dalam marquee wujud **DUA kali** (copy1 + copy2, `ucapan.js:140-150`), jadi state per-kad TAK boleh disimpan pada node DOM, mesti disimpan pusat (Map keyed by ucapanId) dan "dilukis" ke semua node.
- Diff-engine `kemasMarquee` (`ucapan.js:177-207`) prepend/remove node ikut `data-id`. Apa apa butang mesti menumpang dalam `binaKad` supaya ia ikut kad, dan count dilukis semula setiap render, BUKAN diletak sekali masa bina.
- Sasaran bergerak: kad marquee sentiasa hanyut. Butang kecil pada kad bergerak = susah untuk orang tua. Ini punca reka bentuk "tap kad besar dulu, baru sayang" di bawah.
- 90% phone, ramai orang tua: kontras tinggi, sasaran besar, gerak sedikit dan bermakna (earned motion), bukan gerak hiasan berterusan.

## Ciri 1 , Butang Sayang (create-only /sayang)

### 1a. Draf rules tambahan (letak SEBELUM catch-all `/{document=**}`)

```
// Collection SAYANG: reaction "sayang" pada ucapan. Create + read sahaja,
// ikut corak /rsvp 100% , tiada update/delete, tiada auth, tiada usik /rsvp.
match /sayang/{doc} {
  allow read: if true;

  allow create: if
    // Dua medan sahaja, tiada medan asing.
    request.resource.data.keys().hasOnly(['ucapanId', 'masa'])
    // ucapanId = id dokumen rsvp yang disayang (string pendek).
    && request.resource.data.ucapanId is string
    && request.resource.data.ucapanId.size() >= 1
    && request.resource.data.ucapanId.size() <= 64
    // Masa: mesti cap masa pelayan sebenar (elak nilai palsu).
    && request.resource.data.masa == request.time;

  allow update, delete: if false;
}
```

`/rsvp` langsung tidak disentuh, keputusan keselamatan sedia ada (`firestore.rules:37`) kekal.

### 1b. Kira count client-side (onSnapshot, corak sama macam baca /rsvp)

Listener kedua, baca SELURUH `/sayang` (tanpa `where` , elak keperluan composite index; saiz terhad untuk satu majlis). Tally ke Map ikut `ucapanId`.

```
// dalam mulakanDinding(), tambah selepas listener rsvp sedia ada:
const sayangKira = new Map();               // ucapanId -> jumlah (nombor sebenar)
onSnapshot(collection(db, "sayang"), (petikan) => {
  sayangKira.clear();
  petikan.forEach((d) => {
    const id = d.data().ucapanId;
    sayangKira.set(id, (sayangKira.get(id) || 0) + 1);
  });
  lukisSayang();                            // lukis count ke SEMUA node kad
  lukisKaunter();                           // kemas kaunter jujur (ciri 3)
});
```

`lukisSayang()` decouple count daripada diff-engine (selamat dgn copy1/copy2 + insert baharu):

```
function lukisSayang() {
  document.querySelectorAll('.ucapan-kad').forEach((kad) => {
    const id = kad.dataset.id;
    const n = sayangKira.get(id) || 0;
    const btn = kad.querySelector('.sayang-btn');
    if (!btn) return;
    const span = btn.querySelector('.sayang-kira');
    span.textContent = n > 0 ? String(n) : '';   // 0 = kosong, degrade elok
    const ditekan = sudahSayang(id);
    btn.classList.toggle('is-sayang', ditekan);
    btn.setAttribute('aria-pressed', ditekan ? 'true' : 'false');
    btn.setAttribute('aria-label',
      'Sayang ucapan ini' + (n > 0 ? ', ' + n + ' orang sudah sayang' : ''));
  });
}
```

Panggil `lukisSayang()` juga di HUJUNG `render()` (`ucapan.js:245`) supaya node baharu dari `kemasMarquee`/`binaStatik` terus dapat count betul. Kos: `querySelectorAll` <= ~80 node, murah.

### 1d. Klik = event delegation (satu listener, tahan diff)

### 1e. Anti-spam ringan + nota jujur

```
const KUNCI_SAYANG = 'sayangDitekan.v1';       // camelCase, tiada dash
function bacaSayang(){ try { return new Set(JSON.parse(localStorage.getItem(KUNCI_SAYANG)||'[]')); } catch { return new Set(); } }
function sudahSayang(id){ return bacaSayang().has(id); }
function tandaSayang(id){ const s=bacaSayang(); s.add(id); localStorage.setItem(KUNCI_SAYANG, JSON.stringify([...s])); }
function buangTandaSayang(id){ const s=bacaSayang(); s.delete(id); localStorage.setItem(KUNCI_SAYANG, JSON.stringify([...s])); }
```

**Nota jujur (WAJIB difahami pemilik):** localStorage cuma halang tekan berganda pada peranti + browser yang sama. Ia BOLEH dipintas (clear storage, phone lain, mod incognito). Tanpa auth, mustahil kunci "satu orang satu sayang" betul betul. **Untuk majlis kahwin ini OK** , niat butang = luahan kasih, bukan undian rasmi. Kekal create-only tanpa auth; jangan buka `allow update` pada `/rsvp` hanya untuk cegah spam (buka pintu race condition + abuse yang lebih teruk). Boleh tambah had saiz doc dalam rules (dah ada: 64 aksara ucapanId) sebagai lapisan nipis.

## Ciri 2 , Tap kad = overlay fokus baca (sentuhan, ask c)

**Kenapa overlay, bukan "besarkan kad di tempat":** kad marquee bergerak dan hidup dalam track dua salinan; membesar di tempat akan rosakkan tinggi track + loop mulus, dan langgar diff-engine. Overlay `position:fixed` berada DI LUAR `#ucapanSenarai`, jadi diff-engine langsung tak sentuh. Ia juga menyelesaikan "sasaran bergerak": tap mana mana kad (walau bergerak) buka satu kad PEGUN besar untuk dibaca , sempurna untuk orang tua.

Spec:
- Elemen `#fokusOverlay` (fixed, inset:0) + `#fokusKad` (kad tunggal besar, `font-size:var(--text-lg)`, max-width ~34rem, tengah skrin), latar gelap `color-mix(in oklch,var(--color-ink) 70%,transparent)`.
- `role="dialog" aria-modal="true"`, ada butang tutup `×` (min 44px), fokus dipindah ke butang tutup masa buka.
- Buka: `bukaFokus(id)` , cari data dari `dataTerkini`, isi teks/nama lewat `textContent`, papar overlay, `document.body.style.overflow='hidden'` (kunci scroll belakang), DAN `tingkap.classList.add('is-pause')` (jimat bateri: marquee henti sementara terlindung).
- Tutup: tap latar, butang `×`, atau `Escape` , pulihkan `overflow`, buang `is-pause`, kembalikan fokus.
- Overlay turut ada butang Sayang besar (guna `tekanSayang(id)` sama) , inilah laluan utama orang tua: tap kad besar, tekan hati besar yang PEGUN.

**Elak langgar scroll phone:** overlay fixed + `body{overflow:hidden}` semasa buka; kandungan overlay pendek (satu ucapan) jadi tiada scroll; kalau ucapan panjang, `#fokusKad{max-height:80vh; overflow:auto; overscroll-behavior:contain}` supaya scroll dalam overlay tak bocor ke body.

**Sentuh-henti sedia ada dikekalkan:** `pasangPause` (`ucapan.js:102-108`) kekal , tahan-jari = jeda pantas untuk glance; tap penuh = buka overlay. Dua tingkah tak berlanggar (tap ringkas vs tahan).

```
.fokus-overlay{position:fixed;inset:0;z-index:50;display:grid;place-items:center;
  padding:var(--space-5);background:color-mix(in oklch,var(--color-ink) 70%,transparent);
  opacity:0;visibility:hidden;transition:opacity var(--dur-mid) var(--ease-out);}
.fokus-overlay.buka{opacity:1;visibility:visible;}
.fokus-kad{background:var(--color-cream);border-radius:var(--radius-lg);
  padding:var(--space-7);max-width:34rem;width:100%;max-height:80vh;overflow:auto;
  overscroll-behavior:contain;transform:translateY(8px);transition:transform var(--dur-mid) var(--ease-out);}
.fokus-overlay.buka .fokus-kad{transform:none;}
```
Reduced-motion: transition auto ke 0.01ms (global) , overlay muncul serta merta, tetap berfungsi.

## Ciri 4 , Heart-burst masa tekan (efek visual, ask b)

Gerak yang DIEARNED (hanya bila user betul betul tekan), bukan ambient. 4 hingga 6 hati kecil timbul dari butang, naik + pudar ~800ms, CSS transform sahaja, node dibuang lepas habis (macam corak buang `.ucapan-kad--baru` di `ucapan.js:84`).

```
function hatiBurst(id){
  if (REDUCED.matches) return;                 // hormat reduced-motion
  const btn = document.querySelector('.ucapan-kad[data-id="'+CSS.escape(id)+'"] .sayang-btn');
  if (!btn) return;
  for (let i=0;i<5;i++){
    const h=document.createElement('span');
    h.className='hati-timbul'; h.textContent='♥'; h.setAttribute('aria-hidden','true');
    h.style.setProperty('--dx',(Math.random()*40-20)+'px');
    btn.appendChild(h);
    setTimeout(()=>h.remove(),850);
  }
}
```
```
.hati-timbul{position:absolute;left:50%;bottom:100%;font-size:.8rem;color:var(--color-plum);
  pointer-events:none;animation:hatiNaik 800ms var(--ease-out) forwards;}
@keyframes hatiNaik{
  0%{opacity:0;transform:translate(-50%,0) scale(.6);}
  25%{opacity:.9;}
  100%{opacity:0;transform:translate(calc(-50% + var(--dx)),-46px) scale(1);}
}
```
(butang perlu `position:relative` supaya hati berlabuh padanya.) Kos: 5 node sementara, transform sahaja, GPU-friendly, auto-buang. Reduced-motion: terus di-skip.

**Refine kad baru (kekal):** kilauan emas sedia ada (`styles.css:483-501`) dah elegan dan terikat pada peristiwa sebenar (kad masuk). Cadang KEKAL tanpa ubah , contoh gerak yang betul.

## Risiko

1. **Sasaran bergerak + butang berganda (paling besar):** heart pada kad marquee kecil dan hanyut, susah untuk orang tua; dan kad wujud 2 salinan jadi count mesti dari Map pusat + `lukisSayang()`, bukan per-node, kalau tidak count desync antara copy1/copy2. Mitigasi: laluan utama = tap kad , overlay pegun , tekan hati besar; heart inline cuma bonus.
2. **Listener kedua (`/sayang`) baca seluruh koleksi setiap perubahan.** Terhad untuk satu majlis (ratusan hati), OK. Kalau meletup luar jangka, boleh tukar ke kiraan aggregate kemudian , tapi tak perlu sekarang.
3. **Anti-spam boleh dipintas** (localStorage). Diterima untuk majlis; jangan over-engineer dengan auth atau `allow update`.
4. **Scroll vs overlay:** kalau lupa `body{overflow:hidden}` + `overscroll-behavior:contain`, scroll boleh bocor. Dah dispec.
5. **Interaksi baharu dalam diff-engine:** WAJIB panggil `lukisSayang()` di hujung `render()` supaya node yang di-prepend `kemasMarquee` dapat count; kalau lupa, kad baru tunjuk count kosong sampai snapshot sayang seterusnya.

Semua ciri hormat `prefers-reduced-motion`, guna `.textContent` (XSS), transform/opacity (bateri), tak sentuh `/rsvp`, `firebaseConfig.js`, atau `pengantin.html`, dan degrade elok bila ucapan/sayang sikit.
